# ADR 0015: 要確認レシートの端末内一時Inbox

## Status

Accepted

## Context

ADR 0014でHigh confidenceの単体レシートは自動保存し、Lowまたはuncertainだけを確認画面へ送る方針へ変更した。最初の縦切りでは要確認ドラフトをReactの画面状態だけに保持していたため、ホームへ戻る、再読み込みする、PWAを終了すると確認対象が失われた。例外だけ確認する運用では、利用者がその場で修正しなくても後から確実に戻れるInboxが必要である。

要確認にはレシート画像とOCR全文が含まれる。これらをFirestoreへ保存すると、クラウド画像保存、家族間共有、保持期間、Security Rules、費用を新たに設計する必要がある。最初のInboxにその範囲を持ち込まない。

## Decision

- 要確認レシートは、撮影したブラウザのIndexedDBだけに一時保存する。
- active household IDでscopeし、ログアウト中や別の家計簿では表示しない。
- `pendingReceiptReviews` object storeを追加し、IndexedDB versionを1から2へ上げる。
- version 2へのupgradeでは既存の `expenses`、`categories`、`receiptImages` を変更・削除しない。
- ホームにこの端末の要確認件数を表示し、既存確認画面で後から修正・保存できるようにする。
- 確認して支出を保存した場合、明示的に破棄した場合、データ初期化した場合、作成から7日経過した場合に一時レコードを削除する。
- 起動時と最も早い期限到達時に期限切れを削除する。
- 要確認中の画像は確認に必要な一時データであるため、確定後の「レシート画像保存」がOFFでも最大7日だけ端末内へ保存する。確定後は既存設定に従い、OFFなら画像を支出へ保存しない。

## Data Model And Migration

`PendingReceiptReview` は次を保持する。

- ID、household scope、画像Blob、元ファイル名、MIME type
- OCR全文と任意の座標block
- `receiptParser.ts` の候補
- 編集前の支出入力値、カテゴリ候補、Confidence判定と理由
- 作成、更新、期限日時

この型は端末内の一時処理状態であり、`Expense`、Firestore、CSV、Google Sheetsのschemaを変更しない。JSONバックアップには含めず、バックアップ置換でも暗黙削除しない。データ初期化では削除する。

## UX

- High confidenceの通常フローにはInbox操作を追加しない。
- 要確認がある場合だけ、ホームの撮影ボタン直下に件数を表示する。
- 確認画面から戻っても要確認を残し、明示的な削除操作を提供する。
- 件数は「この端末に一時保存」と表示し、家族の別端末へ同期されると誤解させない。

## Security And Privacy

- 画像、OCR全文、Confidence理由をFirestore、運用ログ、分析サービスへ送らない。
- InboxはGoogle Vision Proxyでの処理後にブラウザ内へ保存し、Proxy側の非永続化方針は変えない。
- 保存期間は7日固定とし、利用者が確認画面から即時削除できるようにする。
- ブラウザのサイトデータ削除、プライベートモード、容量不足では消える可能性がある。
- household scopeで別家計簿との混在を防ぐ。ただし、同じhouseholdへ参加する利用者が同じブラウザprofileを共用する場合は端末内Inboxを共有する。
- 将来クラウド同期する場合は、端末内暗号化、認可、保持期間を別ADRで再検討する。

## Alternatives Considered

- OCR全文と入力値だけを保存し画像を保存しない: 再確認時に原本と比較できず、誤った総額の修正が難しいため採用しない。
- Firestoreへ要確認データと画像を保存する: 別端末で確認できるが、クラウド画像保存と家族共有のプライバシー範囲が大きくなるため初期採用しない。
- 画面状態だけを維持する: 再読み込みや後回しに耐えず、例外確認モデルが成立しないため継続しない。
- 期限なしで端末へ保存する: 個人情報と容量が不要に残るため採用しない。

## Consequences

- Lowまたはuncertain結果をその場で修正せず、後からまとめて確認できる。
- 同じ端末での再読み込みとPWA再起動に耐えられる。
- 家族の別端末には要確認件数も内容も同期されない。
- IndexedDB schema migrationと一時画像の容量が増える。
- Inboxの端末間共有が必要になった場合は、画像保存先、暗号化、認可、削除、費用を新しいADRで決定する。
