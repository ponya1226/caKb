# ADR 0020: 品目合計の決定論的な要確認ゲート

Date: 2026-08-15

## Status

Accepted

## Context

Google Visionが支払総額を正しく読み取っていても、長い食品レシートでは一部の商品行だけが品目候補から欠落することがある。従来の `receipt-confidence-v1` は品目合計と総額の差を最大15%まで許容し、不一致を警告に留めていた。そのため、総額が正しければ不完全な品目明細をHigh confidenceとして自動保存できた。

品目明細は支出集計の正本ではないが、取得したように見える明細に抜け漏れがある状態は利用者が発見しにくい。実例では税抜品目合計5,195円、税額415円、総額5,610円に対し、抽出品目が3,028円分しかなく、税額415円も誤って品目へ含まれていた。

## Decision

- 品目候補が1件以上ある場合、次のどちらかが整数円で完全一致するときだけ品目整合性を `consistent` とする。
  - 品目合計 = 支払総額
  - 品目合計 + 抽出した消費税額 = 支払総額
- 税額は `receiptParser.ts` で品目候補とは別の一時的な解析信号として抽出する。
- 複数税率やOCR上の重複表記に対応するため、同額の重複を除いた印字税額の合計だけを照合に使う。ただし完全一致以外は採用しない。
- 品目候補があるのにどちらにも一致しない場合、`line_items_inconsistent` をblocking理由として要確認へ送る。
- 品目候補が0件の場合は `unknown` とする。単品レシートや明細を持たない形式を一律に要確認へ送らない。
- 手動の確認・編集後は、税、値引き、ポイント等の事情を利用者が確認した上で、品目合計と総額が一致しなくても保存できるADR 0008の方針を維持する。
- 判定ルールを `receipt-confidence-v2` とし、端末内品質集計でv1と分離する。

この決定はADR 0014の「品目不一致だけでは要確認にしない」と15%許容の実装を、自動保存判定に限って置き換える。

## Data Model

`ReceiptParseRiskSignals` に任意の `taxAmounts` を追加し、`ReceiptConfidenceSignals` に照合根拠 `lineItemMatchBasis` を追加する。いずれも読み取り中または要確認中の一時状態であり、`Expense`、Firestore、CSV、バックアップのschemaは変更しない。既存の要確認データに新フィールドがなくても `unknown` として読み込めるため、IndexedDB version変更は不要である。

## UX

- 一致する通常レシートには操作を追加しない。
- 不一致時だけ「品目に抜け漏れがないか確認してください」と既存確認画面へ案内する。
- 確認画面では品目の追加、修正、削除を継続して利用できる。
- 支出再編集モーダルは、長い品目明細でもスマホのソフトウェアキーボード表示中にフォーカスした入力欄まで縦スクロールできるようにする。

## Future AI-assisted Check

任意のレシートをAIで再確認する機能は今回実装しない。将来検討する場合は、次を最低条件とする。

- 利用者が対象レシートを明示的に選んだ場合だけ実行する。
- 週1回などのhousehold単位上限をサーバー側で強制し、クライアント時刻だけに依存しない。
- 送信する画像、読み取り文字、品目、保持期間、利用する外部サービス、費用上限を新しいADRで決定する。
- AI結果だけで支出を自動変更せず、抜け漏れ候補と根拠を表示して利用者が確定する。
- レシート内容をログへ出さず、secretをフロントエンドへ置かない。

## Alternatives Considered

- 従来の15%許容を維持する: 小さな差には強いが、品目欠落をHighとして保存するため不採用。
- 品目候補がないレシートも必ず要確認にする: 操作が大きく増え、品目を持たないレシート形式も止めるため不採用。
- 税率から税額を再計算する: 端数処理、複数税率、内税・外税で誤差が生じるため不採用。印字された税額だけを使う。
- 直ちに外部LLMを導入する: プライバシー、費用、評価方法、回数制限が未決定のため不採用。

## Consequences

- 品目が途中まで抽出された長いレシートは、自動保存されず確認対象になる。
- 税抜商品価格のレシートでも、印字税額との完全一致により通常フローを維持できる。
- v2ではv1より要確認率が上がる可能性があるため、理由別件数と実レシート結果を確認して調整する。
- 支払総額を正本とする既存の月次・年次・カテゴリ集計は変わらない。
