# UI Writing Guidelines

caKbの利用画面では、技術の仕組みではなく、利用者が行う操作と得られる結果を伝える。

## Standard Terms

| 内部・技術文書 | 利用画面 |
| --- | --- |
| OCR | レシート読み取り、文字を読み取る |
| Google Vision / 高精度OCR | オンライン読み取り |
| Tesseract.js / ローカルOCR | 端末内読み取り |
| Firestore | クラウド |
| IndexedDB / local | この端末、この端末に保存 |
| JSON | バックアップ、バックアップファイル |
| Google Sheets | Googleスプレッドシート |
| export | 書き出す |
| import / migration | 読み込む、コピーする |

正式な製品名や保存方式は、README、ADR、セットアップ手順、ログ調査などの開発・運用文書では使用してよい。

## Action Labels

- ボタンは「実行」「処理」だけにせず、`オンラインで読み取る`、`支出一覧を書き出す`、`バックアップから追加`のように結果が分かる動詞を使う。
- 取り消せない操作は、対象と結果を確認文に含める。
- 同じ操作には画面をまたいで同じ語を使う。

## Errors

- Proxy、環境変数名、内部エラーコード、Rules、API keyなどを通常画面へ表示しない。
- `通信状態を確認する`、`正しいURLで開く`、`管理者へ問い合わせる`など、次の行動を示す。
- 原因を断定できない場合は断定せず、再試行や代替手段を案内する。

## Required Notices

平易な表現にしても、次の事実は省略しない。

- レシート画像が外部サービスへ送信されること
- 画像をcaKbのサーバーへ保存しないこと
- クラウド保存時に家族へ共有される範囲
- データの削除、置き換え、初期化の結果
- オフラインや端末内保存でデータが失われる可能性
